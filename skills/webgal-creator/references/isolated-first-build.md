# Creator 隔离首版

适用于从已审核的 Markdown 制作新的线性 WebGAL 首版。使用启用了本机 firstBuild 配置的 MCP。已有或已交给 Terre 编辑的项目走原来的保存交接。

1. **准备一次制作授权。** 先完成剧本审核、素材来源决策和素材核对。记录 story.md 的 SHA‑256。给用户看新工程、拟创建或修改的场景、素材及其来源、要设置的配置项，以及本地试玩交付方式。每个素材记录来源 ID、相对路径、源文件版本、目标类别和目标相对路径。批量列出完整范围，收到对本次制作的明确同意后，用用户本次原话调用 first_build_begin。只有已确认的场景、素材与配置键进入授权。造型变化、需付费的准备、新来源等有独立决策时先处理。
2. **制作为多个受控批次。** 用 first_build_inspect 读取隔离工程配置或具体场景及其版本。使用已有的 WebGAL 转写和分页规则。按常规批次上限编排并保留本次制作记录，优先写好被引用的素材与场景。每批重新读取 story.md 并核对其哈希。剧本变化时先撤销授权并请求确认。在哈希吻合时调用 first_build_apply，带上同一 runId、storyRevision、该批操作和全新的批次键。多批共用原授权。工具替每批生成并提交正式计划，做校验、备份、读回和回执。遇到临时候选诊断，修正后按原范围重试。调用超时可以用同一批键和完全相同的操作查回已核对的回执，忙碌时等待在途批次结束。
3. **处理确认或恢复。** 收到 FIRST_BUILD_CONFIRMATION_REQUIRED，立即停止本次写入。使用 first_build_inspect 查看状态和可核对批次，向用户说明超出的路径或改动、当前磁盘状态和可选择的处理方式。保留隔离目录、快照和回执。需要新的制作授权时按用户选择重建隔离首版，或在用户明确接手并建立 Terre 映射后按既有交接处理。连接关闭、用户取消、授权过期和成品交付均结束本次授权。本地记录留在本次构建目录。重连后用原 runId 调用 first_build_inspect，只读查看已核对和待核对的批次。回执表示当时的读回结果。
4. **本地预览与交付。** 所有拟交付批次完成后检查保存版扫描与相关场景。调用 first_build_preview（deliver: false）取得只读快照及 snapshotId，进行 Chrome 抽查。有必要时在授权范围内修正并重新预览。核对后调用 first_build_preview（deliver: true），传入最后核对的 snapshotId。服务核对入口场景、清单内的所有必交场景与素材，交付同一个快照。报告本地播放链接、用户可接手的本机路径及未实测部分。链接在 MCP 连接存续期间可用，工程和快照保留。用户若要在 Terre 打开，另行明确交接到一个新目标，或走现有工程写入流程。

隔离首版使用现有的普通场景、配置和素材操作，包括普通大素材。需要 Live2D 整包或精选绑定等专用导入时，先与用户确认本次的替代素材，或选择使用普通 Terre 受控流程。工作区和预览都由 MCP 管理。Creator 的私有剧本与制作记录放在工程外，并以 runId 和 storyRevision 核对身份；正式 Terre script-map 在用户接手、登记并核对保存版本后建立。
