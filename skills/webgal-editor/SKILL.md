# WebGAL Editor

Use the registered webgal MCP and Node.js 24. The source of truth is the current project's saved scene. A hand-authored game needs no Creator installation, story.md or script-map.json. Creator’s reviewed Markdown, casting notes and synchronization map are read-only to Editor. A draft goes to stdout and the chat. If intermediate files are needed, create a fresh private temp directory for this edit. Never reuse an existing review, story or notes file as scratch space.

只问做法或验收标准时，采用题面已给的台词、对象和状态。信息足够就给建议与可观察的预期，跳过工作区搜索。请求定位实际片段、交付修改或检查实际画面时，再按对应流程读取保存场景、候选或预览。

## 修改正文时

只拆本次目标，以保存场景和本次认可的替换文字为准，范围外逐字节保留。按语义、说话者和阅读节拍把正文切成可手动翻过的页。中文旁白可从每页 30–50 字、对白 15–40 字起步，超过 60 字优先检查；按实际模板、字号、头像和混排宽度调整。保留可读字号、原标点、引号和空格。每页明确说话者；无名旁白清名，心声沿用稿中约定。普通阅读页保留手动停页，避免用 `-next`、`-continue` 自动推进或用 `-concat` 把分开的页重新接长。

从最终候选 TXT 用工程对应的 WebGAL parser 读回每页正文，按顺序拼回认可文本，另核对姓名。只排除已约定的结构分隔；出现首个差异就定位修正。遇到转义、注音、样式或变量时分别核对脚本含义和实际显示。Chrome 抽查最长页、最宽混排页及对白转旁白处（可重合）：关 AUTO，等末字完全显现，亲看正常游戏截图中首末字、姓名框与控制列，再手动翻页。回想和 `scene_validate` 的命令摘要不能替代这两项检查。

拆带语音或条件的句子时，核对每页是否还在同一分支。整句录音只触发一次；确认翻页时不会无意截断。若已有分句录音，按对应文本绑定。听完整句才发生的反应留在末页之后。只改音乐或立绘时保留原文分页。

## Locate and preview

复核指定场景的立绘演出时，按[关键反应与叙事焦点](../webgal-staging/references/figure-and-composition.md#关键反应与叙事焦点)从保存场景标出触发句、涉及的角色、预期画面和回场点。对进入本次编辑范围的节拍出局部 diff；核对候选的 `scene_validate` 命令与素材引用，预览时按[反应与焦点切换](../webgal-staging/references/visual-validation.md#反应与焦点切换)抽查。

在场普通 PNG 移动后换表情，本入口下方的移动和差分规则足以生成脚本：已知活动 ID、槽位、触发页和两张对齐的图片时直接编写。若素材留边、遮挡或相机取景仍有具体疑问，再读[立绘与构图](../webgal-staging/references/figure-and-composition.md)。硬切时需核实退场参数的登记时机，可直读[转场与时序](../webgal-staging/references/transitions-and-timing.md)。

从入口能确定命令、对象、节拍和预期画面时，直接输出脚本。需要补资料时只取解决缺口的一页，按入口目录折叠相对路径中的 `..`；等正文返回后复用，同一实际文件只请求一次。其他演出可查已安装的[演出索引](../webgal-staging/SKILL.md)。普通改字与基础分页留在本入口。

返工时沿用每一轮的「已试写法 → 实际画面」及本次可改范围，再选下一个不同的修法。交接时在对话或已有的私有验收记录中带上这几行，让新会话也能看到；保持游戏脚本纯净。

When the requested cue introduces a Live2D model or changes the performance of a figure whose saved entry is a Live2D model, load the optional sibling [webgal-live2d](../webgal-live2d/SKILL.md). For a PNG expression swap, dialogue or music edit, continue here even when other models are present.

For background music, use `bgm:track.mp3 -next;` to start or switch tracks and `bgm:none -next;` to stop. Use the exact project-relative filename within `game/bgm`. To bring back a previous track, issue its `bgm` cue again. Map each cue to the requested dialogue gap: opening music precedes the first line, and a change after an announcement follows the complete announcement. Validate the exact candidate with `scene_validate`: at every inserted music line, check the sentence's `command` is `bgm`, including the stop cue. An unknown keyword such as `changeBgm` can parse as `say` with no syntax error. Correct the cue and revalidate before presenting the draft.

For start/switch/stop insertions, use the local helper's `mode: "bgm"` with the original `scene_read` snapshot, `projectId`, and ordered `cues`. Each cue takes `line` (the 1-based line to insert before), `before` (that exact saved line) and `track` (filename or `"none"`). It returns the ready-to-send sparse `operation`, `candidateText`, `afterRevision` and receipt. Send its exact `operation` to `change_plan` and its exact `candidateText` to `scene_validate`. Require the plan's operation `afterRevision` to equal the helper's `afterRevision` before handing off. A mismatch means the planned scene differs from the checked one; rebuild the draft from the helper output. For edits to existing music commands or custom options use the ordinary draft helper and make the same revision comparison.

For a sequence of entrances, reactions and exits, trace the active ID, slot and transforms along the saved path, including earlier changes in the candidate. Place cues in dialogue gaps. Keep the original expression through the complete triggering line; keep the departing actor visible through the farewell, absent during the wait and present again just before the return line. Clear named figures by active ID and anonymous figures by slot. For insertion-only work, removing the added cues must reproduce the original scene bytes.

For an expression-only edit to an active static image in 4.6.7, prefer `changeFigureDiff` with its active ID or anonymous slot. Keep the pose and costume consistent. When a full `changeFigure` replacement is needed, repeat the slot and explicit ID and carry over effective position, scale and framing. Keep implicit center implicit. Compare a fixed body point before and after the swap, and check the other figures stay in place.

For an approach or retreat, move the specified actor and leave the other still. Target its ID or active `fig-left`, `fig-center` or `fig-right`. Let a line establish both positions; a natural approach can precede the mover's next reply. Account for both slot origins and offsets. Choose a destination relative to the mover's own origin that leaves both silhouettes readable. A quick move may take about 180–300 ms; adjust to the beat.

Use the helper's `move` mode for a horizontal move. Pass `firstLine`, `before` (the exact unchanged anchor line), `target`, numeric destination `x`, and `duration` in milliseconds along with the saved snapshot. It inserts one WebGAL `setTransform` cue and retains the original line, its voice/options and all other dialogue. Pass its returned operation directly to the draft plan. Check the diff adds only the movement cue. In a playback check, compare the two figures before and after the cue and check the original dialogue sequence.

1. Resolve the intended project with `webgal_status` and `project_inspect`. Verify the project mapping before a handoff. Page through `scene_list`; resolve a named location using filenames, labels, background cues, dialogue and incoming scene links as needed. Read plausible scenes with `scene_read`.
2. Match the user's *spoken text* within the requested scene, speaker and context. Inspect the raw commands alongside `scene_validate` sentence ranges from the same revision. Account for options, comments, explicit speakers, narrator forms, speaker carry-over and multi-line commands. Exclude stage commands, commented lines and hits in arguments. For an ordinal, count matching utterances in saved script order **after** resolving scene and speaker. Apply a clear ordinal directly. If branching, unidentified speakers, multiple scenes or cues leave plausible alternatives, show each scene, line, speaker and neighboring context and ask the user to choose. A missing match merits a short explanation or close candidates.

Page through `asset_list` for the correct kind (BGM in bgm, effect in vocal). Resolve ambiguous assets by relative filename with the user. Check existing engine/project syntax for timing and staging. Place the cue in the chosen gap, respecting whether it happens before or after the utterance. Preserve surrounding commands, comments, argument order, voice and formatting. If the requested scope depends on a conditional, confirm the cue runs on the same path. For a pause, confirm the supported timing command and units.

## Helper

If the helper reports `Saved bytes disagree with scene_read`, refresh the snapshot and build the request from its complete text, including the final line ending. In a shell that alters multiline or Unicode input, use the file-writing tool to save the UTF-8 request JSON to a fresh private path, then pass those bytes to the helper (PowerShell 7: `$OutputEncoding = [Text.UTF8Encoding]::new($false); Get-Content -Raw -Encoding utf8 -LiteralPath $requestFile | node $helper`). The helper checks the scene inside the JSON. A shortened probe or placeholder paired with the real revision will always fail that check.

Run `node <installed-skill>/scripts/local-edit.mjs`. Send UTF-8 JSON on stdin. In PowerShell 7 use `$OutputEncoding = [Text.UTF8Encoding]::new($false)` and `$payload | ConvertTo-Json -Depth 20 -Compress | node $helper`, where `$payload.scene` is the complete original scene_read object. Preserve the returned text, encoding, revision and line endings. It writes JSON to stdout and exits nonzero on conflict. All modes require the verified `projectId` and original `scene` from `scene_read`.

- `mode: "find", needle` lists literal line hits and adjacent text. Use a short dialogue substring so quotes, options or alternate speaker spellings do not hide candidates. Determine semantic matches from the saved commands before counting.
- `mode: "draft", firstLine, lastLine, before, after` takes a reviewed 1-based inclusive range (`lastLine` defaults to `firstLine`). Supply the complete exact lines, excluding the last line terminator. Include the adjacent dialogue if inserting/removing a whole stage command. Output contains a single UTF-16 `edit_scene` operation, predicted `afterRevision` and a reversible local `receipt`. For distant blocks in one file, individual drafts may be reviewed and applied as separate batches with independent approvals.
- `mode: "undo", receipt` produces a reverse draft against the current saved scene. The receipt is the inner object from the original helper result. A changed file requires unique matching applied text and recorded neighboring context. Inspect staging dependencies for semantic drift as well. Any conflict requires user choice.

## Handoff, apply and readback

1. Ask the user to save successfully and close **all editing pages for this project**. Wait for their explicit current reply. Begin `write_session_begin` using the draft's exact `paths`, `decision: "saved-and-editors-closed"`, and the user's actual statement. Keep the same MCP connection.
2. Re-read the scene and relevant dependencies. Compare to the reviewed snapshot and the intended ordinal, surrounding cues and asset choice. For drift end the session. Show baseline, current text and proposal. Offer to keep the hand edit, retarget or make a new draft on top of it. Even unrelated changes need a freshly reviewed draft against the new revision. Never shift an old ordinal onto another line automatically.
3. Generate `change_plan` again with the session ID and the reviewed operation. Compare its paths, before/after revisions, diagnostics and diff to the draft. Present the formal plan ID and local diff. Wait for separate explicit approval of this plan. If the session expires, end/reopen with fresh handoff and repeat formal approval.
4. Keep a local private receipt **before** applying, e.g. under the user's home directory in `.webgal-editor/receipts/<projectId>/<planId>.json` (use safe filenames). Store the verified project identity including preview URL, timestamp, pending status, plan ID, idempotency key and helper receipt. Use a new file per plan, outside all game roots and Git. Apply the exact plan with `change_apply`. Read the scene back and compare its raw revision to the predicted after hash. Recheck affected lines and references via `scene_validate`. Record the result and end the session. For failed, partial, uncertain or missing replies, inspect by plan ID and resolve any lock warnings before asking the user to reopen. Reuse an idempotency key only for the same plan. Report the plan ID and actual readback. When requested, spot-check only the changed location in Chrome.

## History and undo

For “what changed”, verify the project binding and use `recovery_inspect({projectId,planId})` plus the receipt to show the actual batch status and local before/after. If the ID is unknown, page history with `includeCompleted:true` and match private receipts. Clarify which change if there are several plausible matches. Inspect an interrupted pending record before considering an undo.

For an applied edit, read the current scene and use the reverse helper. Preview its diff and follow the same handoff, formal plan approval and readback. Save a new receipt with the original plan ID as `undoOf`. Later edits outside the uniquely identified block are preserved. If the target or staging dependencies were hand-edited, show original, applied and current passages and ask what to keep. If the receipt is unavailable, `recovery_inspect` still provides batch history. Offer `recovery_restore` only for explicitly selected files whose *entire current version* matches the batch output, with fresh handoff and separate approval of the restore scope. A file version mismatch requires a reviewed local edit or user resolution.
